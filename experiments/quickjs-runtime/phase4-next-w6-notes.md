## What the runtime did before

- A program is one named function declaration (`entrySource`). Script top-level
  code, global `var`/`let`/`const`/`class` and top-level `this` cannot be
  written (compiler rejection, unchanged).
- Free names: QuickJS emits `get_var`/`get_var_undef`/`put_var` on closure refs
  of type 3 (`JS_CLOSURE_GLOBAL_REF`; nested functions chain type 3 to the
  entry). `program.js` turned them into per-closure cells only for the literal
  intrinsic table (Math, JSON, Number, Object, Array, Function, String,
  Boolean, 7 Error constructors, parseInt, parseFloat, NaN/Infinity/undefined
  immutable) and the entry's own name; any other free name (`globalThis`,
  undeclared names, `typeof x`, implicit globals) was a compiler SyntaxError
  `Unsupported global or module reference: X`.
- `push_this` in sloppy code boxed primitives; an undefined/null receiver was
  runtime status 6. There was no global object.

## Model implemented (host-verified; GPU pending)

Two packing modes, chosen per program by `globalProgramPlan`:

- **classic** (bit-identical packing): no sloppy `push_this` in a user
  function, no free name outside the intrinsic table, no `delete x`. Such a
  program can never reach the global object, so its intrinsic cells are
  consistent by construction.
- **global-object mode** (`image[0].w` bit 17): every global reference of every
  user function (intrinsics and the entry name included) is a property
  operation on the single global object; bootstrap helpers keep their cells.
  - `get_var x` -> `get_global a=text(x) b=0` (ReferenceError when
    `HasProperty(global, x)` is false), `get_var_undef` -> `b=1` (typeof),
    `put_var` -> `put_global` (strict: ReferenceError when unresolvable; then
    `[[Set]]` with the existing strict TypeError rules, setters via
    continuation 2), `delete_var` -> `delete_global`.
  - Global refs use capture spec 7 (no cell; `closure()` skips them).
  - Global object = **fixed node 65**: kind 2 ordinary object,
    `[[Prototype]]` = node 1 (`%Object.prototype%`), extensible. Initialized in
    `main()` only in global-object mode, before the entry closure; ES2025
    clause 19 order: `globalThis` (W,!E,C, value = node 65), `Infinity`, `NaN`,
    `undefined` (all false), `parseFloat` 1781, `parseInt` 1780, `Array` 200,
    `Boolean` 137, `Error` 600, `EvalError` 606, `Function` 500, `Number` 122,
    `Object` 100, `RangeError` 603, `ReferenceError` 602, `String` 136,
    `SyntaxError` 604, `TypeError` 601, `URIError` 605, `JSON` node 25,
    `Math` node 23 (W,!E,C). These are the same value encodings the classic
    capture specs produce. The check enforces this against `program.js`.
  - Entry binding (CreateGlobalFunctionBinding): `{W, E, !C}` after the closure
    exists. A same-named configurable intrinsic (`function Math(){}`) is
    redefined in place.
  - Sloppy `push_this` with an undefined/null receiver pushes node 65.
- GC: node 65 is a fixed root (`PHASE4_FIXED_ROOTS`); properties hang from its
  `next` and use ordinary kind-3/9 nodes, so no new heap kind is needed.

### Explicit boundaries (fail closed)

- Unimplemented ES2025 globals (`globalUnimplementedNames`: eval, isNaN,
  isFinite, URI functions, Symbol, BigInt, Map, Set, Weak*, Promise, Proxy,
  Reflect, RegExp, Date, typed arrays, ArrayBuffer, DataView, Atomics,
  Iterator, AggregateError, FinalizationRegistry, escape/unescape):
  identifier references are still compiler-rejected with the old message. On
  the global object they are `prototypeGap`s of node 65: Get -> status 6,
  `in` -> true (correct), own-property queries, delete, defineProperty and
  creation by assignment -> status 6.
- Full own-key lists of node 65 (`getOwnPropertyNames`, object spread,
  `__lanesOwnPropertyKeys`) -> status 6. `Object.keys(globalThis)` and for-in
  are exact, because every intrinsic global is non-enumerable.
- `make_var_ref`/`get_ref_value`/`put_ref_value`/`with_*`/`put_var_init` stay
  rejected (unsupported instruction). None of the tested global forms
  (assignment, compound, update, for-in/of target, destructuring) emits them.
- Entry functions named `NaN`/`Infinity`/`undefined`: CanDeclareGlobalFunction
  is false, which is a script-level TypeError that the single-function format
  cannot express. Compiler rejection `Unsupported global function declaration`.
- Known shared engine deviation, documented and not admitted: in strict code,
  `x = rhs` where `x` is unresolvable when the reference is evaluated but `rhs`
  creates it. ES2025 6.2.5.6 says ReferenceError; QuickJS and V8 store
  (`stored3`). QuickJS bytecode has no operation at reference-evaluation time,
  so the GPU follows QuickJS (`globalKnownDeviationCases`).
- Host-defined facets: the design is spec-pure, with no host properties and
  `[[Prototype]]` = Object.prototype. `Object.prototype.toString.call(globalThis)`
  is `"[object Object]"`, while QuickJS and Node add a host `"global"` tag. This
  is recorded in `globalHostCases`. Node's global also has a non-Object.prototype
  prototype.

### Phase 3 hooks (no symbols yet)

- `Symbol`/`BigInt` globals: add rows to `globalBindings` (identity = the
  Phase 3 constructor value), remove them from `globalUnimplementedNames`, and
  add the classic literal mapping in `program.js`. The check fails if the
  `program.js` literal table and `globalClassicIntrinsicNames` diverge.
- A host `@@toStringTag` would be an own symbol-keyed data property of node 65.
- Symbol-keyed own properties of node 65 must follow string keys in `ownKeys`
  (the full list is still status 6 here).

### Reservations

Fixed node 65 is used (`phase4-fixed-nodes.js` already documents it). The table
in PHASE-4-NEXT-STATUS.md still says "27 (if needed)" and should say 65.
Builtin IDs 2110–2139, heap kind 36 and continuations 66–67 are reserved but
unused. Three opcodes are appended: `get_global`, `put_global`,
`delete_global`. FIELDS are append-only: `globalThis` plus any missing
unimplemented global names.

## Consequences for existing suites (lead-owned files)

- 96 corpus programs switch to global-object mode, all for the `sloppy-this`
  reason, e.g. `function g(){return this.value}` called with a receiver.
  Their results are unchanged, but their intrinsic references now pack as
  `get_global`, so they are not bit-identical. Every one of their opcodes has a
  WGSL case. The other 2,224 admitted corpus programs pack bit-identically
  (code and image, excluding the FIELDS append). If the lead prefers zero
  churn, drop the `sloppy-this` trigger in `globalProgramPlan`. Sloppy
  `this` = undefined/null then stays status 6 unless another trigger applies.
- Newly admitted, previously compiler-rejected: w7 edge u8, u9, u10, u11.
  Previously status 6, now values: w7 edge u1–u7 and
  `n-template:sloppy-tag-this-global`. Three `boxingUnsupportedSources`
  entries also contain sloppy `this` and now pack in global-object mode. Their
  unsupported reason may be unrelated, so recheck them. Move the records in
  `phase4-edge-cases.js` / `phase4-template-tagged-cases.js` /
  `phase4-suite-expected.js` / `check-phase4-edge.mjs` (its "status-6 evidence"
  assertion). Their V8 expectations are already recorded and equal what this
  design computes. Equivalents are in `globalCases`.
- `phase4-regression-cases.js` `unsupported-with` is still rejected, but the
  message changes from `Unsupported global or module reference: a` to
  `Unsupported QuickJS instruction: with_get_var`.
- `test262-outcome.js` keeps classifying `Unsupported global or module
  reference: X`, because that message is unchanged for unimplemented globals.
